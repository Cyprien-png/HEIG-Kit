# High quality videos (`hqvideo` module)

Explanatory videos drawn in React, HTML and SVG and rendered with [Remotion](https://www.remotion.dev), frame by frame in
a headless Chromium: polished typography, cards, glows, circuits, tables, step-by-step explanations in 1080p, with a
natural French voice or silent with subtitles. Everything runs on your computer.

The [`visuals`](visuals.md) module (manim) remains the right tool for curves, geometry and LaTeX-heavy mathematics, and
renders faster. When you ask for a video without saying which kind, the assistant asks: normal or High quality, with or
without audio.

## Setup

```sh
npm run setup -- hqvideo
```

Installs, without touching the rest of your system (about 6 GB):

- Remotion and React in `modules/hqvideo/node_modules`, and Remotion's headless browser in `node_modules/.remotion`;
- [OmniVoice](https://github.com/k2-fsa/OmniVoice) in `vendor/omnivoice`, with its own Python environment, PyTorch and
  its model (deleting that folder removes the voice);
- FFmpeg, with your system's package manager.

The setup ends by checking the example video. Remotion is free for individuals; companies need a
[license](https://www.remotion.dev/license). The OmniVoice model is published under CC BY-NC: its voice is for
non-commercial use.

## Usage

A video is two files with the same name: `<name>.tsx`, its scenes, and `<name>.narration.json`, what is said in each
scene, line by line.

```sh
npm run hqvideo -- video.tsx --check             # errors and an image of the key frames, in seconds
npm run hqvideo -- video.tsx --open --frames     # silent video with subtitles (1080p), opened
npm run hqvideo -- video.tsx --audio --open      # with the spoken narration
npm run hqvideo -- video.tsx --quality medium    # 720p; low = 540p
npm run hqvideo -- video.tsx --no-subtitles
npm run hqvideo -- --where                       # default folder used by the assistant
```

Try it with the example, a complete exercise of the SYL course on multiplexers:

```sh
npm run hqvideo -- modules/hqvideo/examples/mux.tsx --audio --open --out ~/Desktop
```

In Claude Code, the `heig:hqvideo` skill writes and renders the video for you: *"fais-moi une vidéo High quality qui
explique l'exercice 4 de la série 6 de SYL, avec audio"*. Videos go to `~/Documents/HEIG-Kit/videos`.

## How it works

- **The narration sets the pace.** Each line lasts as long as its speech, or as long as it takes to read it in a silent
  video, and the scenes place their animations on the start of the lines (`useLines()`): the same scenes work with and
  without sound.
- **Scenes are pure functions of the frame.** A scene is a React component that draws frame `f`; nothing plays in real
  time, so every frame is rendered exactly, in parallel browser tabs, and assembled with the sound by FFmpeg.
- **The voice is the same everywhere.** OmniVoice clones the voice of `modules/hqvideo/voice/reference.wav`, itself
  generated by the model: every video and every computer gets that voice. Spoken lines are cached in `.cache/hqvoice`:
  rendering again only synthesizes the lines whose text changed.
- **`heigkit`** (`modules/hqvideo/kit/`) gives the look and the ready-made pieces: colors, header, value chips, truth
  tables with grouped rows, multiplexers with a lit path, values flying from one place to another.

On an 8-core Mac (M1 Pro), a 3-minute video takes about 2 minutes to draw, plus about 20 seconds per new spoken line.
The voice uses the graphics card when there is one (Apple Silicon, NVIDIA); on a server without one it runs on the
processor and takes several times longer.

## Remote server

The `render` container of the [remote server](server.md) includes this module, its browser, the voice and its model:
`render_hq_video` queues a job like the other renderings, followed with `get_job`.
